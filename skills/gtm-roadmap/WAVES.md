# The four waves — detailed spec

How to design each rung of the warmth ladder. For every wave, the roadmap specifies eight things: **audience · list-building (source + tool) · message strategy · lead-magnet role · channel(s) · cadence/volume · autonomy level · success metric.** Data uses the same tooling as the `icp-definition` skill (see its SIGNALS.md); sending uses whatever channels you have connected — a LinkedIn automation tool, an email sequencer, WhatsApp. Network import and sends are **omnichannel** — not LinkedIn-only.

---

## Wave 1 — Existing network (warmest)

The single fastest path to value. The founder already has trust banked here; we're spending it, not building it.

- **Audience:** everyone the founder already knows who matches the ICP — *plus* contacts who don't match but can **refer/intro** to those who do. Don't discard non-ICP contacts; reclassify them as referral sources.
- **List-building:** **import the entire network across channels** (LinkedIn connections export, Google/email contacts, phone/WhatsApp), then **score each contact against the ICP brief's fit signals** (enrich + filter). Output two lists: *direct prospects* and *referral sources*.
- **Message strategy:** **warm A-C-A**, hyper-personalized to the real shared history. Reactivate dormant ties. Give-first: open with the relationship, offer the lead magnet, ask the easy-yes. (See [HORMOZI-OUTREACH.md](HORMOZI-OUTREACH.md).) For referral sources: ask for the intro, not the sale.
- **Lead-magnet role:** a warm gift ("made this for you / your team") — reinforces an existing relationship rather than proving competence to a stranger.
- **Channel(s):** wherever the relationship actually lives (DM, email, WhatsApp) — not forced onto one platform.
- **Cadence/volume:** one-time burst through the whole matched list, paced human-naturally; the warmest get a 1:1 hand-written touch.
- **Autonomy:** **co-drafted, human-approved, never auto-sent.** These are the founder's real relationships — highest stakes on the ladder.
- **Success metric:** positive-reply rate + meetings booked (expect the highest of any wave).

## Wave 2 — Schedule / event-relational

A real-world reason to talk. Relational context lands far better than a cold ping.

- **Audience:** ICP (and warm network) **in the place the founder will be** — a city they're travelling to, a conference/event they're attending.
- **List-building:** start from the founder's **calendar / travel + event plans** (`[owner]` — ask, or read a connected calendar). Cross-reference with the network and the ICP by geography/event (people search with geo/keyword filters; event attendee lists where available).
- **Message strategy:** warm outreach with a **real-world hook** — *"I'll be in [city] for [event] on [date] — saw you're there/based there, worth a coffee?"* Invitation, not pitch. Time-boxed urgency is built in.
- **Lead-magnet role:** secondary — the meeting is the CTA; the magnet is a follow-up or a reason for the meeting ("I pulled something for you, easier to walk through in person").
- **Channel(s):** DM/email; whatever gets a fast yes before the date.
- **Cadence/volume:** bursty and **recurring** — fires whenever the calendar gains a trip/event. Small, high-intent lists.
- **Autonomy:** human-approved (still relational and date-sensitive).
- **Success metric:** meetings/coffees booked per trip.

## Wave 3 — ICP × tribes (parallel experiments)

The first properly cold wave — warmed by a **shared tribe**. This is also the **learning engine**: run tribes against each other and find the message that wins.

- **Audience:** strangers who match the ICP **and** belong to one of the founder's tribes (ICP brief §6 — alma mater, ex-employer, accelerator, community, shared investor).
- **List-building:** **one list per tribe.** People/company search with the ICP fit filters, then intersect with each tribe via education, experience history, group memberships, etc. (see the `icp-definition` skill's SIGNALS.md).
- **Message strategy:** **cold value-first**, opened by the honest tribe commonality — *"Fellow [tribe] — [give]."* **One variant per tribe, run in parallel**, identical structure so the comparison is clean. Follow-up sequence, not a single send.
- **Lead-magnet role:** central — the give that earns a stranger's reply; the tribe just buys the first second of attention.
- **Channel(s):** primary outreach channel(s), consistent across variants so the test is fair.
- **Cadence/volume:** moderate per tribe — enough to read a reply rate, capped so a losing message doesn't burn a whole segment.
- **Autonomy:** **semi-autonomous** — agent drafts per tribe, human approves the template, sends at test scale, learns.
- **Success metric:** **positive-reply rate by tribe** → pick the winning tribe(s) + message. That winner becomes the **Better** baseline (HORMOZI-OUTREACH.md) for Wave 4.

## Wave 4 — Always-on ICP signals (durable engine)

The background machine. No tribe required — the **timing signal is the honest excuse to reach out**, so it works on any ICP-fit stranger.

- **Audience:** any ICP-fit account/person with a **live timing signal**, tribe or not.
- **List-building:** **continuous signal detection** off the ICP brief §5 timing signals (hiring, funding, job-change, relevant post, expansion) via the SIGNALS.md map (job posts, post search, funding/news, role tenure…). Always running.
- **Message strategy:** **cold, signal-led** — *"Saw [trigger] — [personalized give]."* Uses the **winning message from Wave 3** as the default, personalized per prospect. Multi-touch follow-up; Rule-of-100 volume once the funnel is proven.
- **Lead-magnet role:** central and **per-prospect personalized** (the magnet engine) — generated fresh off the prospect's own public data when the signal fires.
- **Channel(s):** omnichannel, prioritized by where the ICP responds.
- **Cadence/volume:** **always-on, high volume**, throttled by signal flow and per-account limits.
- **Autonomy:** **autonomous with guardrails** — detect signal → generate magnet → draft + send within the approved template → **escalate any reply to a human.** The deepest rung of graduated autonomy.
- **Success metric:** signal → send → positive-reply funnel; meetings booked; cost per meeting. This is the metric that proves the system scales.

## Putting it on a timeline

Waves are **not strictly sequential** — they overlap and change character over time:

- **Wave 1** front-loaded: a one-time burst in week 0–1 (biggest early win).
- **Wave 2** opportunistic: fires whenever the calendar fills; recurring forever.
- **Wave 3** ramps once Wave 1 is sent: 2–4 weeks of parallel experiments to find the winning message.
- **Wave 4** switches on after Wave 3 names a winner, then **runs indefinitely** as the durable engine.

So: warm bursts up front for fast value → tribe experiments to learn the message → always-on signal engine for durable, scalable flow. Front of the ladder buys time-to-value; the bottom buys a machine.
