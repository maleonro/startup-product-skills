# Lead Magnet Design

Second skill of the GTM set (`icp-definition` → `lead-magnet` → `gtm-roadmap`). Goal: turn the core offer into a **lead magnet** — *a complete solution to one narrow problem* — that earns the prospect's attention by giving real value first.

A lead magnet is value delivered before any ask, so outreach built on it reads as *"thank god you reached out"*, not spam. It feeds both halves of GTM — **outreach** (a reason to message that isn't a pitch) and **positioning** (content that gives the win in public).

Frameworks come from Hormozi — see [HORMOZI-LEADMAGNETS.md](HORMOZI-LEADMAGNETS.md). Inputs come from the [`icp-definition`](../icp-definition/) brief and the offer.

## The core idea (don't lose this)

A great lead magnet **solves one narrow problem completely** — and solving it *reveals the next, bigger problem that only the core offer solves.* Give the win in full (never tease); the gap it opens is what creates the pull to buy. A watered-down teaser fails; one that attracts freebie-seekers instead of the ICP is worse than none.

## The best lead magnet: personalized × high-value × zero-effort (default to this)

What converts best is not a generic downloadable — it's **a done-for-you artifact, personalized to the specific prospect, that they did nothing to receive.** Maximize all three at once:

- **High value** — something they'd genuinely pay for or act on.
- **High personalization** — about *them and their company specifically*, not their segment.
- **Zero effort for them** — already done, in their hands. No form, no call, no homework. (Effort moves to *you* — which is fine, because agents can do it at scale.)

> The give *is already the deliverable.* The prospect's reaction should be *"wait, you made this for me?"*

**AI makes this scalable.** Because an agent can gather public data and generate the artifact per prospect, you can do at scale what used to be a manual, high-touch favor. So you usually aren't designing one static asset — you're designing a **magnet engine**: a repeatable recipe of *public inputs → personalized artifact*, run once per prospect.

**The discovery is creative and tailored, not a template.** For each offer, ask: *what could we find or compute about this exact prospect, from public sources, that proves we can solve their problem — and reveals they have it?* Mine widely (see [PERSONALIZED-MAGNETS.md](PERSONALIZED-MAGNETS.md)). Example — a company that *sells lead generation*: the magnet isn't an ebook, it's **a report with 10 qualified leads for that prospect, each with a ready-to-send icebreaker.** Translate that move to your offer.

## Workflow

1. **Load the offer + ICP.** Read the core offer and the ICP brief (`icp-definition` output) if it exists. You need: the dream customer, the dream outcome the paid offer delivers, and the persona's pains. Don't design a magnet for "everyone."

2. **Mine the narrow problem.** From the ICP's pains, pick **one** problem that is: (a) real and urgent for the ICP, (b) solvable in a quick win, and (c) *adjacent to the core offer* — so solving it surfaces the bigger problem the offer solves. Narrow beats broad.

3. **Hunt the personalization angle (do this first, before generic ideas).** Ask: *what could we gather or produce about each specific prospect, from public data, that delivers the win already done?* Brainstorm the sources and the "you made this for me" artifact ([PERSONALIZED-MAGNETS.md](PERSONALIZED-MAGNETS.md)). This is the creative core — spend real thought here. Fall back to a non-personalized magnet (calculator, guide) only if no personalized angle is feasible.

4. **Generate 3–5 candidates, then score.** Mix personalized-engine ideas and any fallbacks. For each pick a **type** + **format** ([HORMOZI-LEADMAGNETS.md](HORMOZI-LEADMAGNETS.md)) and score against the quality bar below and *"does solving this pull them toward the core offer?"* Pick the winner; keep a fallback.

5. **Design the winner as an engine.** If personalized: specify the **data-gathering recipe** (exact public sources + tools per prospect), the **generated artifact** (what the prospect receives), the **quick win**, and the **bridge** — how the artifact reveals the next problem and hands to the core offer's CTA. If static: specify the complete solution + bridge.

6. **Name it + show a worked example.** Draft 3–5 names (value obvious and specific). For the engine, generate one **worked example** for a real sample prospect, so everyone sees exactly what lands.

7. **Plan production + distribution.** What it takes to build the engine (data pipeline, generation, cost per prospect — kept low by automation), and how it's deployed: the artifact *is* the outreach opener (tied to a timing signal + tribe from the ICP brief), plus the public/content version.

8. **Write the spec.** Produce the markdown deliverable using [TEMPLATE.md](TEMPLATE.md). If you're in a code repo, save it *outside* the repo (or ask). Flag assumptions explicitly.

## Quality bar (Hormozi + personalization)

- **Personalized to the prospect.** About *them and their company specifically*, not their segment.
- **Zero effort for the prospect.** Already done, in their hands — no form, call, or homework.
- **Narrow + complete.** Solves *one* problem, *fully*. No teasing.
- **Reveals the next problem.** The win exposes the gap only the core offer fills — that's the engine, not a coincidence.
- **Quick win.** Fast payoff — builds trust and reciprocity immediately.
- **Worth paying for.** The prospect should think *"they gave this away?"*
- **ICP-aligned.** Attracts the dream customer specifically — not tire-kickers.
- **Cheap to deliver at scale.** Per-prospect generation must be automatable, or it won't run across a list.
- **Has a reason-why + a clear next step.** Say why it's free; every magnet ends pointing at the core offer.
